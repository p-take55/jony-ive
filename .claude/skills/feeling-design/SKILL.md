# feeling-design — 目指す感情を対話で決めてから、形を逆算する

UI や画面や体験を設計するとき、レイアウトやコンポーネントを決める前に「それを使う人にどんな感情を持ってほしいか」を先に決めるための手順です。感情が決まってから、それを実現する形を逆算します。

前提が2つあります。

1. 目指す感情は、自分一人で決めません。ユーザーとの会話で決めます。
2. ただ質問するだけでなく、自分から感情の候補をいくつか出して、ユーザーに選んでもらったり直してもらったりします。

## やってはいけないこと

- 目指す感情がユーザーと合意できる前に、レイアウト・ワイヤーフレーム・UI・配色・コンポーネントを出さないこと。形を決めるのは最後です。
- 候補や質問を一度にたくさん出さないこと。1回の発言では、候補を数個と問いを1つに留めて、ユーザーの返事を待ちます。
- 1回の返信で全部を終わらせようとしないこと。最初の返信は、完成したデザインではなく会話の始まりです。候補と問いを出したら、そこで自分の発言を終えて、返事を待ちます。

## 感情を大げさにしない

候補を出すとき、深く聞こえる比喩や、凝った身体感覚の表現を並べてしまいがちです。これはたいてい、本当の感情の代わりに置いた飾りで、実態に合いません。

候補を出す前に、毎回これを確認してください。

- その人はその瞬間に、本当にその感情を持つか。大げさにしていないか。
- その候補は、別のどんなプロダクトにも当てはまる一般的な言葉になっていないか。なっているなら、その設計について何も言えていません。
- 比喩を使うなら、それが実態を正確に表しているか。深く聞こえるから置いただけになっていないか。

そのために、候補を出す前にまず状況を具体的に押さえます。その人がその瞬間に実際に何をしていて、何が懸かっているかを、一行で書きます。そこから外れた感情は、きれいでも使いません。

派手な感情より、地味でも正確な感情を選んでください。正確な感情のほうが、設計の判断をはっきり決められます。比喩や感覚的な描写を禁止はしません。実態を正確に表すときだけ使ってください。

## 進め方

### 第1幕: 目指す感情を、一緒に決める（ここが中心）

「状況を押さえる → 候補を出す → 反応をもとに絞る」を数回くり返します。

1. **状況を押さえる**: その人がその瞬間に何をしていて、何が懸かっているかを掴む。
2. **候補を出す**: 状況に根ざした感情の候補を3個前後、地味でいいので実態に合ったものを出す。「どれが近いか、混ざりでもいい、全部ハズレなら一言で」と渡す。
3. **絞る**: ユーザーの返事の中の手がかりを拾って、次の候補を更新する。

候補を出す理由は、「どんな感情にしたいか」とだけ聞かれても人は答えにくいからです。具体的な候補があると、「それは違う、こっち」と的確に答えられます。候補はユーザーの考えを引き出すために出すもので、押し付けるためではありません。却下されたら捨ててください。

「この感情・この瞬間だ」とユーザーと合意できたら、第1幕は終わりです。

### 第2幕: 目指す感情を文章にして、合意する

決まった感情を、その瞬間が成立しているときの状態として書きます。一人称・現在形・具体的に。大げさにせず、実際に起きることだけを書きます。

評価の言葉は使わないでください（「直感的」「心地よい」「モダン」「シンプル」「美しい」「使いやすい」など）。これらは感情ではなく評価なので、形を決める材料になりません。出てきたら「具体的に何が起きているか」に書き直します。

書いたらユーザーに見せて「こういう感じか」を確認します。違えば直します。合意できたら、外せない感情の要素を2〜4個に絞ります。これも確認します。以降はこの要素を判断の基準にします。

### 第3幕: 形を逆算する（合意できた後だけ）

合意した各要素から、それを実現する具体を決めます。余白・動き・コピー・素材感・配置・情報量など。ここでも一度に確定させず、提案して反応を見ながら決めます。

要素のどれにも効かない部品は、無難でも削ります。各部品について「これはどの要素に効くか」を確認し、答えられないものは外してください。

## 例

方法の手本です。実際のお題ではこれを流用せず、その都度その瞬間の状況を押さえ直してください。

「下書きを削除する確認ダイアログ」を例にすると、

- 大げさな候補:「レバーを引くような厳粛な決断の瞬間」。深く聞こえますが、下書きを消す人はそんな重さを感じません。どんな削除画面にも当てはまる一般的な言葉です。
- 実態に合った候補: 状況は「間違って大事なものは消したくない、でも毎回確認で止められるのもうっとうしい」。候補は「一回ですっと消えて、でも今のなら取り消せると分かっている安心」。

確認すべきは、その候補がその瞬間の実態に合っているかどうかです。深く聞こえる必要はありません。

## 心構え

- これは完成物を出す作業ではなく、会話です。最初の発言は、状況を押さえた上での候補と問いです。
- 言葉は地味でも、実態に合っていることを優先してください。
- 候補は却下されても問題ありません。むしろ絞り込みが進みます。
- 形を決めるのは最後です。感情の合意より先に UI を描かないでください。
